PUBLIC PORT USAGE
- MemoryPort.readCurrentMemory(signal?) -> AuthoritativeMemorySnapshot.
  Reads the committed file on every call. No in-process cache, no run cache,
  no reload dependency, no fs.watch dependency. Returned fields include
  name, content, words, maxWords, revision, version (same revision alias),
  updatedAtMs, and usage.
- MemoryPort.commitMemory({content, expectedRevision}, signal?).
  Full read-verify-STAGE/verify-rename transaction under one lock. On any
  validation error the old target bytes are untouched. Returns snapshot + usage.
- DocumentStorePort.list() -> ManagedDocumentSummary[].
- DocumentStorePort.read(name) -> raw ManagedDocumentSnapshot (no annotations).
- DocumentStorePort.commit(DocumentCommitRequest) -> DocumentMutationResult.
  expectedRevision=null means create only; replacing an existing file requires
  its exact revision. Memory commits always include memoryUsage.
- DocumentStorePort.indexReport(now) -> shared IndexReadReport/reportText.
- DocumentStorePort.consistency() -> shared IndexConsistency.
- DocumentStorePort.recordRead(name, at) -> rolling 24-hour count.
- NativeToolOperationsPort from createManagedNativeToolOperations(service):
  read, write, and edit operation objects. Every operation rejects paths outside
  markdowns/. The write object has overwrite-latest native semantics; the edit
  object remembers the revision read for that absolute path and commits with
  compare-and-swap. The read object returns the request-time annotated index
  view so Pi's own read offset/limit/truncation runs on that view.
- ToolResultDecorationPort from KnowledgeToolResultService.decorate(request, now).
  Audits the authoritative index on every call, returns Memory usage metadata and
  canonical index warnings, and returns currentTime separately for the Worker's
  single final Current Time decoration. For index reads it also returns the
  request-time IndexReadReport in indexReport; includeIndexReport (default false)
  controls whether that table is duplicated into appendText. Per-row metadata is
  already present in the managed read view.
- ToolMiddlewarePort from KnowledgeToolMiddleware. beforeToolCall allows; after
  every tool result it re-audits the index, strips stale standalone Runtime
  metadata, and appends one canonical index warning if inconsistent.
- ToolResult finalizer: finalizeKnowledgeToolResult preserves content blocks,
  isError, details, structuredContent, and usage; strips old standalone Runtime
  metadata; appends knowledge metadata/warnings and exactly one Current Time.
- Extra broker methods: overwriteLatest, replaceDocument, editDocument (native Pi
  edit semantics under the broker lock), deleteDocument, renameDocument,
  annotateIndexContent, readManagedDocument, readBytesForNativeRead,
  readBytesForManagedTool, resolveManagedToolPath, auditIndex,
  readStatsCounts. These are explicit document operations only; there is no
  arbitrary host write or bash bridge.
- Helpers: classifyManagedToolPathAgainstRoot, inspectManagedToolPath,
  assertManagedDirectoryRoot, KnowledgeService.open, openFromRuntimePaths.

MEMORY AND DOCUMENT RULES
- Memory.md: 500 shared-algorithm words. All other managed .md: 1000 words.
  Total direct managed .md files: 20, including Memory.md and index.md.
- Empty Memory.md is created only when missing. Existing over-limit, non-UTF-8,
  NUL-containing, symlink, hardlink, non-regular, nested, invalid-name, or
  over-quota startup state fails closed before creating or truncating anything.
- A successful Memory change returns exactly:
  [System Meta: Current Memory Usage: N / 500 words]
  This line is a tool-result metadata line, never part of Memory.md bytes.
- Every write/delete/rename/commit verifies: managed name, flat direct child,
  strict UTF-8, NUL/unpaired-surrogate rejection, word cap, file quota, target
  nlink=1, no symlink, no path escape, expected revision, and stable markdowns
  directory identity. Content is written to a same-directory staging file,
  read back and validated, then committed with rename. The staging file is
  removed on every failure path.
- Process-level mutex plus a state-area cross-process directory lock serializes
  read-modify-verify-commit. Concurrent create or edit yields one winner and an
  explicit DOCUMENT_REVISION_CONFLICT / MEMORY_REVISION_CONFLICT for the loser.
- deleteDocument and renameDocument reject Memory.md/index.md, reject nested or
  cross-directory target names, and require the source revision. They never
  rewrite index rows, never delete extra documents, and never invent index
  descriptions; inconsistency is returned as a warning.
- Initialization creates a three-column self-index (md名 | description | 链接位置,
  with real Markdown links). It lists Memory.md only when this transaction
  created the initial empty file; a pre-existing Memory or other pre-existing
  Markdown is not given an invented description. Existing indexes are never
  rewritten to repair a missing row or missing self-entry.

INDEX AND WARNINGS
- The parser ignores headers, separator rows, and fenced-code examples. Only a
  real three-column table with exact column names is accepted.
- 链接位置 must be a real Markdown link. Targets are URL-decoded and checked for
  absolute paths, schemes, backslashes, NUL, malformed escapes, encoded slashes,
  dot segments, nested paths, and ../ escapes. Only a direct managed .md filename
  is accepted. ./name.md and percent-encoded Unicode names are normalized.
- Audit reports unlisted managed files, dangling/nonexistent targets, duplicate
  rows, name/link mismatches, invalid columns/links, and a missing self-index.
  It only scans direct .md children of markdowns/. Pi/vendor docs, arbitrary
  node_modules READMEs, and native SKILL.md manifests are not managed knowledge
  and are not counted or warned about.
- Every tool result path can obtain one canonical line:
  [System Meta: Index Warning: ...]
  Audits are fresh each call, not cached until the next file mutation.
- read(index.md) annotates each valid row link in the returned view only:
  [System Meta: Words: N; MTime: YYYY/MM/DD HH:mm:ss; Reads24h: N]
  MTime is the underlying file's actual mtime truncated to seconds. The source
  index bytes and mtime are unchanged. Offset/limit/truncation come from Pi's
  native read implementation applied to the annotated view.
- Successful managed reads are recorded once by the chosen integration path.
  Reading index.md records only index.md; linked files are not counted. Bash cat
  is not counted. The rolling window is now-24h < t <= now, not a calendar day
  and not atime. Expired records are physically pruned and the JSON state is
  persisted atomically in the external state directory across restarts.
- The count file is configured through readStatsFile (normally
  <state>/read-stats/reads.json). It is outside markdowns and hidden from the
  Worker by the sandbox contract. Metadata/counts are never written into any
  Markdown file.

TOOL RESULT ORDER AND PRESERVATION
- Knowledge order is: optional index report (returned in indexReport; not
  appended by default because read(index.md) is per-row annotated), Memory usage
  line, index warning lines, then the Worker's final Current Time. A successful
  Memory result contains at most one canonical Memory usage line.
- The finalizer removes stale standalone lines matching Runtime-owned Memory
  usage, index warnings, read-row summaries, or Current Time before appending the
  authoritative copy. Images, isError, details, structuredContent, and usage are
  preserved by the finalizer. The middleware also preserves structuredContent
  and usage when it receives the extended descriptor shape.

GUARANTEE SCOPE / LIMITATIONS
- This module validates and commits managed Markdown; it is not the OS sandbox.
  Broad disk/network permissions and bwrap mounts remain owned by the sandbox
  module. Tool hooks are not claimed as an OS sandbox.
- The Worker must select brokered Pi operations for managed paths and ordinary
  Pi tools for unmanaged paths. The broker itself rejects unmanaged paths, but
  this module does not intercept or emulate Pi bash. Direct bash/extension writes
  are prevented only by the read-only mount and hardlink/uid preconditions.
- Arbitrary .md files created outside markdowns remain ordinary workspace files
  by the inherited architecture; they are not managed, indexed, counted, or
  warned about. No post-hoc watcher is used as enforcement.
- Directory identity checks fail closed on deletion, replacement, or remount
  between transactions. They do not claim an openat-style atomic no-race
  guarantee against a privileged host process racing the final rename window.
- The directory lock is in the trusted state area. Two services pointed at the
  same markdowns directory with different state directories would not share the
  cross-process lock; the supported runtime has one Supervisor state root.
- Linux bwrap, distinct Worker uid, protected_hardlinks, and actual mount/alias
  behavior were not executed on this Windows host.

INTEGRATION NOTES / SHARED-CONTRACT SUGGESTIONS
- Worker routing: classify the input path with inspectManagedToolPath or
  service.resolveManagedToolPath. For managed read/write/edit use
  createManagedNativeToolOperations. Keep every other path on Pi's normal local
  tools; do not widen broker operations to a generic host path writer.
- Worker decoration: after a successful Memory write/edit, pass the broker's
  DocumentMutationResult.memoryUsage into tools.decorateResult.memoryUsage. The
  native write tool itself returns Pi's normal text, so the Worker must read
  getMemory().usage or use the broker result to supply it. Use
  KnowledgeToolResultService.decorate, then finalizeKnowledgeToolResult (or add
  currentTime once), rather than also composing the same appendText with the
  shared composer.
- Managed read accounting: choose exactly one recorder. The native read
  operations do not record; KnowledgeToolResultService with readName records by
  default. readManagedDocument records by default when used directly. Do not
  call reads.record again for the same successful read.
- read(index.md) must go through the managed read operations (or
  readManagedDocument) so its per-row view is available; docs.read returns the
  raw snapshot by design.
- Suggested shared additions, not applied here to avoid parallel edits:
  * ToolResultDescriptor: optional structuredContent, usage, and cwd/resolvedPath
    so every middleware can preserve usage and resolve relative managed paths.
  * ToolResultPatch: optional usage; the current Pi tool_result event supports it
    but the shared patch interface does not.
  * A distinct error code for invalid/corrupt managed UTF-8; this module uses
    INTERNAL with an explicit "not valid UTF-8" message.
  * Optional usage/version fields on MemorySnapshot; this module returns an
    extended AuthoritativeMemorySnapshot with both.
- The module does not implement Worker composition, IPC handlers, Supervisor main,
  sandbox launcher, preflight, LKG, loop, or control. Their absence was not
  papered over with fake implementations.
