二、四个工作流实际接线

1. Preflight
- 首次 baseline 与所有 Supervisor/Worker reload 都走外部 static + Mock preflight，不在 Supervisor 导入候选代码。
- 生产请求使用 `process.execPath` 和 `args=[entry]`；cwd 在 protected/hidden root 之外的 staging 目录；candidate/result/stderr 路径映射到 sandbox 视图。
- 诊断文件 no-follow/单硬链接/dev-ino 复核；超时杀完整候选进程树并返回诊断。
- 保留 `preflight-child-executable.test.ts` 并通过；新增/保留 `preflight-launch-contract.test.ts`、`preflight-stderr-alias.test.ts`、`runtime-reload-preflight-start.test.ts`。

2. Provider / model
- 候选加载前安装 ModelRuntime guard；loader 返回后、bindCore flush 前检查 pending provider/native/virtual 注册。
- initial bind、reload beforeSessionStart、session_start、replaceSession/recovery 都安装 provider API guard；拒绝错误结构化可见，route/baseUrl/api 不变。
- 保留 `reload-provider-api-guard.test.ts` 原 3 个回归并通过；`reload-provider-boundary.test.ts` 覆盖 computed/保留引用、tool/command、startup/reload/replaceSession。

3. Reload rejection / candidate cleanup
- loader 已切换或新 runtime 已建立后的失败先恢复 previous approved set；恢复失败才退出交 Watchdog。
- `reload-rejection-loaded-state.test.ts`、`runtime-reload-rejection-cleanup.test.ts` 通过：被拒绝候选的 tool/MCP/context hook 不残留、不可调用。

4. IPC / Watchdog / sleep
- Worker 启动经 stdin 接收一次性 token；首帧认证绑定 launchId/generation/session；第二 peer/重放/旧代际事件拒绝。
- Watchdog 用 Supervisor 启动 handle 的宿主 bwrap PID 做 exit/kill/monitor；namespace PID 只记 `reportedWorkerPid`；旧宿主 PID 进 retired 集，迟到 exit 不冒充当前 Worker。
- Worker 启动读取持久化 sleep 状态，sleep 中重启上报 sleeping 并保留 deadline。
- 修复 coordinator 队列与 Watchdog 队列的锁反转：reload observer 的 begin/complete/fail 按顺序异步入 Watchdog 队列，不在 coordinator 持锁时 await Watchdog；`watchdog-restart-readiness.test.ts` 通过。

五、Windows local launcher 与生产 bwrap 的明确差异

本机功能测试使用 LocalProcessGroupLauncher / LocalWorkerSandboxLauncher，它们只验证 argv/env/路径/生命周期契约。以下均未在真实 bwrap 证明：
- FD 继承/关闭、/proc/self/fd 与 fd 别名；
- PID namespace 中 Worker PID 与宿主 bwrap PID 的对应；
- mount namespace、ro-bind、/proc、/dev、tmpfs、path alias 与 rename；
- 独立 Worker UID/GID、setpriv/newuidmap、supplementary groups、CapEff=0；
- Docker seccomp/AppArmor、volume 权限/恢复、healthcheck、TERM/KILL 和 24H soak。

因此报告不把 local launcher、YAML、compose config 或 skip 当作 Linux 安全通过。
