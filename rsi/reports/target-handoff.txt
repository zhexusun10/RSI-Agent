三、目标前置条件

- Linux 主机；可用 Docker daemon 与 build/run 权限。
- 内核允许 user/mount namespace；非 setuid bubblewrap 且支持 `--disable-userns`；镜像内有 setpriv/newuidmap。
- 宿主 `fs.protected_hardlinks=1`、`fs.protected_symlinks=1`。
- Docker 接受 `rsi/deploy/seccomp-bwrap.json`；如启用 AppArmor，须允许 bwrap namespace/mount。
- 目标机自备人工非空 `.txt` 系统提示词，并配置真实模型凭据/operator settings/models/auth。仓库不提供生产提示词或密钥。
- 不要在目标机增加 privileged、docker.sock、宿主根、额外 Worker capabilities 或 unsandboxed fallback。

四、准确运行路径与命令（仓库根目录）

```sh
docker build --file rsi/Dockerfile --tag rsi-agent:target .

# 生产默认 ENTRYPOINT 有界验收（先跑这个）
node rsi/scripts/linux-validation.mjs \
  --mode docker --suite entrypoint --image rsi-agent:target --no-build \
  --timeout-ms 900000 --report /var/tmp/rsi-entrypoint.json

# Linux/bwrap/reload/LKG/sleep 目标 harness（调试用途，使用 --entrypoint node）
node rsi/scripts/linux-validation.mjs \
  --mode docker --suite target --image rsi-agent:target --no-build \
  --timeout-ms 1800000 --report /var/tmp/rsi-target.json

# 显式 24h（target harness soak，不是生产 ENTRYPOINT soak）
node rsi/scripts/linux-soak.mjs \
  --hours 24 --image rsi-agent:target --no-build \
  --report /var/tmp/rsi-soak.json
```

也可用 `--suite all` 顺序运行 target 再 entrypoint；任一步非 0 都是失败，不是 skip。要求证据文件保留完整退出码/报告；本机因 Windows + Docker daemon 不可用只记录 blocked_environment，不再反复重跑不可能命令。

五、边界与提醒

- 同进程任意 JavaScript 边界：恶意代码一旦作为合法 Worker/插件运行，可复用已认证 IPC 伪造自身 health/reload/settled，也可通过反射/原型/内存改写绕过进程内 provider guard。3 轮健康与 LKG 是 Supervisor 对已认证 Worker 的观察，不是独立外部可信观察者，不能宣称“已攻陷 Worker 仍可信”。
- 托管 Markdown 范围：仅 `/data/markdowns/` 下直接 `*.md` 受 broker 管理（1000 词/篇、总数 20、Memory 500、index 一致）。workspace、plugins、tools、workflows 中可存在不受管的 `.md`，没有全盘白名单。
- operator config 首次基线会接受首次启动时的配置；生产应从已知安全配置启动。
- MCP/Skill：各 5 上限的回归已通过；不鼓励也不批评使用 MCP/Skill，它们不构成安全证明。
- 用户需自行提供人工提示词与模型凭据；无付费 API 自动化。
