PUBLIC PORT CALL ORDER
1. Explicit sleep request:
   sleep tool input exact-one validation -> computeValidatedSleepDeadline (Clock + zone,
   civil-date validation, 24:00:00 normalization, past/overflow checks) ->
   AtomicLoopStateStore transact(active sleep, generationAtRequest, wakeId, notified=null)
   -> arm chunked timer -> emit sleep.requested, sleep.entered, loop.paused ->
   SleepScheduler onSleepEntered -> AutonomousLoop.pauseForSleep -> SleepGrant returned.
2. Sleep deadline:
   timer fire -> wakeDueOnce transact(status=completed, wakeNotifiedAtMs=now) -> clear timer
   -> emit sleep.woke, loop.resumed -> resolve gate waiters -> SleepScheduler onWake ->
   AutonomousLoop.handleSleepWake. A restart sees the same persisted deadline; a future
   deadline is re-armed at the original instant, a due deadline is notified once.
3. Every model/provider request:
   Worker calls SleepGatePort.beforeModelRequest (or installs
   createPiPrepareRequestGate as Pi's prepareRequest hook) -> read external ledger ->
   active future sleep: await async waiter, no polling/blocking loop -> deadline wake ->
   re-read ledger -> allowed only if no active sleep -> stopped runtime rejects the request.
   Native tool follow-up, plugin continuation, queued message, and restart recovery must all
   pass this same hook.
4. agent_settled:
   ignore agent_end -> reject duplicate runId in memory and against persisted
   lastSettledRunId -> generation/session match -> if sleep active, no Supervisor turn ->
   if aborted/queued/operator input pending, no Supervisor turn -> network/provider error
   gets bounded exponential backoff -> otherwise persist one pending continuation ->
   zero-delay timer -> dispatch -> worker.startRuntimeTurn(continuationId, factual Runtime
   message) -> persist accepted/runId. A second settle or pending continuation cannot create
   a parallel prompt.
5. Reload:
   /reload tool or shim or trusted command -> validate request id/reason/candidateId/
   generation/session -> ReloadCoordinator lock (same request id joins, different id is
   rejected retryably) -> preflight -> require report.ok -> require runtime generation
   unchanged -> approve report.generation -> emit reload.preflight/reload.started ->
   apply. Worker apply calls reload.started, then raw Pi reload; failure calls reload.failed
   and returns the original stack to the caller.
6. CLI shim:
   classify argv -> /reload: control request -> response/detail or stack on stderr and
   exit 1 -> forbidden/invalid/unsupported: explicit stderr and exit 2 -> forward: spawn
   real Pi with the original cwd/argv/stdio and SHIM_MARKER_ENV=1.

SLEEP TOOL CONTRACT
- Tool name: sleep.
- Schema properties: exactly duration and until; both optional; additionalProperties=false.
- Runtime requires exactly one present non-undefined field.
- duration: ^([1-9][0-9]{0,14})([smh])$; positive integer only; zero, signs, fractions,
  leading zero, unknown units, unsafe products, and non-representable Date/epoch values fail.
- until: exact YYYY/MM/DD HH:mm:ss. Years 0001..9999, real calendar days, minute/second
  00..59. 24:00:00 is accepted only with 00 minutes and 00 seconds and becomes the next
  civil day 00:00:00; 24:00:01, 24:01:00, and 0000/00/00 fail. Invalid dates are rejected
  before JS Date can roll them (for example 2026/02/30 24:00:00 is rejected).
- Absolute times use the configured IANA zone; default is UTC. Skipped local times fail,
  ambiguous local times choose the earlier instant (shared time contract).
- Errors return isError tool results containing message and stack, not stderr-only logs.

EXTERNAL STATE FILE FORMAT
Path: RuntimePaths.sleepStateFile (default <state>/sleep.json).
This file is the loop/sleep ledger, not a bare shared SleepState object. Consumers must use
SleepScheduler.status()/LoopStateStore.read(), not assume the outer shape is SleepState.
Example shape:
{
  "version": 1,
  "revision": 0,
  "generation": null,
  "sessionId": null,
  "sleep": {
    "version": 1,
    "sleepId": "sleep-<uuid>",
    "source": "explicit-sleep-tool",
    "request": {
      "kind": "relative",
      "duration": { "raw": "5m", "amount": 5, "unit": "m" }
    },
    "requestedAtMs": 0,
    "deadlineMs": 300000,
    "timeZone": "UTC",
    "status": "active",
    "updatedAtMs": 0,
    "generationAtRequest": 1,
    "wakeId": "runtime-wake:sleep-<uuid>",
    "wakeNotifiedAtMs": null
  },
  "continuation": {
    "id": "continuation-<uuid>",
    "kind": "runtime-wake",
    "createdAtMs": 0,
    "status": "pending",
    "sourceRunId": null,
    "dispatchedAtMs": null,
    "acceptedRunId": null,
    "error": null
  },
  "pendingOperatorInputs": 0,
  "stoppedReason": null,
  "lastSettledRunId": null,
  "lastError": null,
  "updatedAtMs": 0
}
- Absolute request form is { kind: "absolute", until: "...", normalizedUntil: "..." }.
- sleep.status: active | completed | cancelled. completed/cancelled keeps the record for
  restart idempotency; a new sleep request replaces it.
- wakeNotifiedAtMs is the exactly-once wake marker. wakeId is stable for the sleep record.
- continuation.status: pending | dispatching | accepted | failed | skipped. A persisted
  pending/dispatching continuation is re-dispatched with the same id after restart; Worker
  must dedupe startRuntimeTurn by continuationId.
- revision increases on every persisted mutation; updatedAtMs is the external Clock.
- Writes use same-directory temp file, mode 0600, fsync, rename over target, directory fsync
  where supported, Windows EPERM/EBUSY/EACCES rename retry, and cleanup of the temp file.
- State directory creation is mode 0700. Reads reject symlink/hardlink/non-file/oversize.

CLI PATH LAYOUT AND ENVIRONMENT
Recommended production layout:
  <shim-dir>/pi              -> rsi/bin/pi.mjs (symlink or wrapper), read-only source path
  PATH                       = <shim-dir>:<real-pi-bin>:...
  RSI_PI_REAL_CLI            = /absolute/path/to/real/installed/pi  (recommended explicit)
  RSI_CONTROL_SOCKET         = <state>/run/control.sock (Unix) or a Windows named pipe
  RSI_CONTROL_TOKEN          = optional protected token from human config/environment
  RSI_SESSION_GENERATION     = current external Worker generation (non-negative integer)
  RSI_SESSION_ID             = current Pi session id
  RSI_CONTROL_TIMEOUT_MS     = optional positive request timeout
- The shim must be earlier in PATH than the real Pi executable. If RSI_PI_REAL_CLI is absent,
  PATH lookup skips the shim's own realpath to avoid recursion.
- /reload is intercepted. install/remove/update/list and native mcp CLI invocations are
  forwarded unchanged. -p/ordinary Pi invocations are forwarded unchanged. Model/thinking/
  prompt/session/credential flags and control aliases are rejected.
- The control token is never written to the ledger, workspace, or source. A Unix socket
  should additionally be protected by state-directory permissions and Worker uid policy.

OPERATOR INPUT POLICY
- Only a successful, persisted sleep enters sleeping state. Agent termination text alone
  never pauses and never creates sleep.
- Human input is delivered through the normal Worker input path. noteOperatorInput records it
  as pending and suppresses an extra Supervisor wake; sleep does not cancel or shorten.
  After the deadline, queued input/continuation is processed under the same model gate.
- A sleeping runtime is not a stopped runtime. Operator shutdown/TERM is the only normal
  stop; it persists stoppedReason, cancels scheduled continuations, aborts the active run,
  clears timers, and does not self-restart in the same process.
