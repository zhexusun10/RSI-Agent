DOCKER / BWRAP POLICY IMPLEMENTED
- Supervisor runs as container root only to call setpriv for the distinct Worker uid/gid 10002.
- cap_drop: ALL plus cap_add SETUID/SETGID/CHOWN for the uid switch and volume repair; no privileged,
  no docker.sock, no host root mount, no published TCP ports, no control API on the network. Compose uses init: true, restart: unless-stopped,
  stop_grace_period 30s, and named volumes rsi-data (/data) and rsi-state (/state).
- The container root filesystem is not made read-only and network egress is not disabled.
- /state/run is setgid group 10002; container-run.mjs continuously tightens a real worker.sock
  to 0660 with the Worker group so the distinct-uid Worker can connect immediately.
- Worker protection is the bwrap policy plus the actual preflight probe, not a relaxed container.
  The probe runs bwrap with user/PID/IPC/UTS namespaces, isolated /proc, --cap-drop ALL,
  --new-session, --die-with-parent, the configured Worker uid/gid, then requires uid match
  and CapEff=0. Failure exits; there is no unsandboxed fallback.
- rsi/deploy/seccomp-bwrap.json is derived from Moby's default seccomp profile and prepends only
  the namespace/mount syscalls bubblewrap needs (clone, clone3, unshare, mount, umount,
  umount2, pivot_root, move_mount, open_tree, fsopen, fsconfig, fsmount, mount_setattr).
  It grants no capabilities.
- Outer no-new-privileges is deliberately not set because setpriv must switch to the distinct
  Worker uid. bwrap sets no-new-privileges and drops all capabilities for the Worker itself.
  Hosts that require an AppArmor exception need an explicit host policy; docs do not recommend
  disabling the sandbox. Startup diagnostics distinguish seccomp/userns, mount/proc, and uid-map
  failures and print CapEff and userns sysctls.

HEALTHCHECK CONTRACT FOR INTEGRATION
- Command: node /opt/rsi/scripts/container-healthcheck.mjs
- File: /state/runtime/health.json, written atomically by the Supervisor at least every
  10 seconds (including during sleep). Health is stale after RSI_HEALTH_MAX_AGE_MS, default
  45000 ms. Required shape:
    {
      "version": 1,
      "updatedAtMs": <epoch ms>,
      "supervisor": { "pid": <pid>, "state": "running" },
      "worker": { "pid": <pid|null>, "state": "healthy|sleeping|starting|restarting|stopped|failed",
                  "generation": <number|null> },
      "sleep": { "active": <bool>, "deadlineMs": <epoch ms|null> },
      "plugin": { "generation": <number|null>, "healthTurns": <number>,
                  "lkgGeneration": <number|null> },   // optional
      "watchdog": { "phase": "idle|healthy|suspect|rollback" } // optional
    }
- Healthy requires: supervisor pid alive and state running; worker healthy with live pid, or
  sleeping with sleep.active=true and a future deadline; watchdog not suspect/rollback.
  Sleeping is healthy. Starting/restarting/stopped/failed are unhealthy. PID liveness is real
  (kill(pid,0)); the file is not trusted alone. Docker uses 30s interval, 10s timeout, 3 retries,
  120s start period.
- The status command prints the same file; no health result is inferred from logs.

OPERATOR CONTROL CONTRACT FOR INTEGRATION
- Socket: /state/control/operator.sock (override RSI_CONTROL_SOCKET), trusted Supervisor only.
- One LF-delimited JSON request: {"version":1,"id":"<uuid>","command":"reload|shutdown|cancelSleep",
  "candidateId":"...","reason":"..."}; one LF-delimited response:
  {"version":1,"id":"<same>","ok":true,"detail":"..."} or ok:false with error.
- rsi/scripts/container-control.mjs implements the client and clear ENOENT diagnostics. The
  integration must implement the server. status reads health.json, not the socket.
- Reload remains: immutable candidate digest -> static TS check -> 3s Mock load -> load ->
  exactly 3 consecutive healthy agent_settled runs -> external LKG. Any crash/hang/missed
  heartbeat/health failure restores LKG. Verification must be repeated after load; digest
  mismatch or fewer than 3 turns cannot promote.

LOGGING / SIGNALS / RESTART CONTRACT
- container-run.mjs starts the actual integration entry, forwards SIGTERM/SIGINT to the
  Supervisor process group, and after a 20s grace sends SIGKILL to the process group and /proc
  descendants. Compose init handles PID 1 reaping. Unexpected Supervisor exit exits non-zero,
  allowing restart policy handling.
- Integration must write logs as append-only files under /state/logs. The wrapper copy-truncates
  *.log every 30s at 16 MiB, keeping 4 files; Docker json-file is capped at 10 MiB x 3.
  This is bounded against unbounded crash-loop disk growth.
